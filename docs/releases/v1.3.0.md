# v1.3.0 — 内置同行会与可回滚的桌面更新

> 发布日期：2026-10-29
> 升级自：v1.2.0
> 数据兼容：SQLite schema 不变，现有数据目录原地保留。

## 重点变化

- 同行会继续以 `/team/` 挂载在科研系统 FastAPI 应用内，由同一个 pywebview 桌面窗口显示，不打开独立浏览器页面，也不需要第二个 EXE 或 CMD。
- Windows 安装脚本把单文件 EXE 安装到 `%LOCALAPPDATA%\Programs\WendaoResearchV3`，并生成桌面、开始菜单图标。数据固定保存在 `%LOCALAPPDATA%\WendaoResearchV3`，与程序目录分离。
- 同行会更新流程改为 PowerShell 原地替换：下载到临时文件、检查 500 MB 上限、验证 SHA-256、验证 ZIP 路径、备份个人数据库、关闭旧进程、校验新 EXE、启动探活，失败时恢复旧 EXE。
- 更新下载使用原子 `.part` 文件，网络失败不会留下半成品；更新日志写入数据目录的 `storage/team_updates/apply_update.log`。
- 版本比较改为数值比较，旧中心包不会诱导降级；启动时会刷新系统版本元数据，修复更新后界面仍显示旧版本的问题。
- 启动实例增加 `/api/app-identity` 身份校验：只复用相同数据目录的本程序实例，不会误连到仍在 5000 端口运行的旧版或同机其他科研系统进程。
- 识别早期 `wendao-v3-clean.db`（缺少迁移账本）并先创建一致性备份，再补账本、迁移到当前 schema；旧库原文件保留，个人主页、设置、任务等数据不丢失。
- 修复 `account_profiles` 使用错误列名 `user_id` 导致个人主页、主题和联机同步返回 500 的问题，统一使用 `account_id`。
- 修复同行会管理端“停用/启用成员”直接写派生列 `accounts.active` 导致的 `cannot UPDATE generated column` 错误，改为更新 `status`，并阻止通过该按钮停用管理员。
- 修复自动更新器的隐藏子进程启动参数：Windows PowerShell 5.1 在 `DETACHED_PROCESS + CREATE_NO_WINDOW + -WindowStyle Hidden` 组合下会立即退出而不执行更新脚本，现改为仅使用 `CREATE_NO_WINDOW`。
- 修复云端部署说明仍使用 `--no-browser` 的问题，统一为显式 `--serve`，避免部署后只绑定 `127.0.0.1` 而外部无法访问。
- 清理管理端账号导出中的临时调试输出。
- 修复二次启动时 `pet_process` 未初始化，以及 `run_local.py` 重复解析启动参数的问题。
- Python 包元数据移除不存在的旧模块，并补上 `pywebview` 运行依赖。

## 数据安全边界

- 自动更新只替换 `WendaoResearchV3.exe`，不会覆盖 `instance/`、`storage/`、`user_config/`。
- 更新前使用 SQLite backup API 创建一致快照；旧 EXE 在新版首次启动成功前保留。
- 多窗口或桌面宠物进程会在替换前退出，避免 Windows 文件锁导致半更新。
- 便携模式仍把数据放在程序旁 `user_data/`；安装模式固定使用 `%LOCALAPPDATA%\WendaoResearchV3`。

## 验证

- 源码测试、个人端自检、同行会自检与冻结 EXE 自检。
- 内置同行会登录页、管理员控制台和更新接口契约检查。
- Windows 图标、桌面快捷方式目标和数据路径检查。

## 已知边界

- 自动替换仅在已打包的 Windows EXE 中开放；源码模式只检查和下载，不执行自替换。
- 如果程序安装在需要管理员权限的目录，更新可能被系统拒绝；推荐使用 `WendaoResearchV3.exe install` 的当前用户安装目录。
- SQLite 仍适合单机和小团队；更大规模协作应迁移到专用服务端。
