## 一、同行会：把两种身份彻底分开

**问题**：之前"同行会"只有一个入口 `/team`，它永远打开本机内嵌的那份中心副本。
当你是成员、连的是别人电脑上的中心时，点进去看到的仍是本机空副本——用管理员的邀请码
注册会报"邀请码不存在或已失效"，到版本中心也找不到对方发布的版本包。
"连接同行会"和"打开那个中心"是两件事，用户无从分辨。

**现在的规则**（身份由本机设置推导，不新增配置项、不改动已有数据）：

| 身份 | 判定方式 | 「进入同行会」打开 |
| --- | --- | --- |
| 中心（host） | 本机中心运行中，或填写的地址就是本机 | 本机中心 `/team` |
| 成员（member） | 已保存中心地址与 API Token，且地址不是本机 | **对方的中心地址** |
| 未选择（unbound） | 两者都不满足 | 身份选择页 |

具体改动：

- 新增 `services/hub_identity.py`：统一推导身份、中心地址、入口 URL 与文案；
- 新增 `web/team_entry.py`：在 `/team` 挂载层拦截——中心身份原样放行；成员身份给出
  "你是成员，数据在 `http://…`"的说明页并直连该中心；未选择身份给出两种身份的选择页；
  `?local=1` 保留为管理员排查本机副本的逃生门；
- 联机页（`templates/online.html`）新增「当前身份」卡片，并把原来自相矛盾的两块拆成
  **A 我是中心**（启动/停止本机中心、成员地址、邀请）与 **B 我是成员**（填地址与 Token，
  保存后入口自动切换），流程不再混在一起；
- 新增 `GET /online/enter`：所有"进入同行会"按钮统一走它，按身份 303 到正确目标；
- 「保存并联机」时若已填地址与 Token 而模式仍是"关闭"，自动切到 `legacy_hub`，
  不再要求先手动改下拉框；成功提示会明确当前身份与入口地址。

## 二、版本包：能下、能校验、能直接用

**问题**：桌面窗口内嵌 WebView 里点"下载版本包"经常没有任何反应（不弹保存框），
成员就以为中心没有包；另外中心库记录的是绝对路径，数据目录一搬动，下载直接 404。

**改动**：

- 新增 `hub/releases.py`：统一的版本包文件解析——绝对/相对路径都认，文件被搬走后按
  文件名在 `storage/hub_releases` 内回退查找，仍限制在该目录内（防路径穿越）；
- 中心端下载（页面与 `/api/v1/releases/{id}/download`）都走同一解析器，返回
  `Accept-Ranges`、`no-store`，文件确实缺失时给出**可执行的原因**："请管理员在版本中心
  重新上传"，而不是空白 404；
- 页面下载支持 `?token=<我的 API Token>`：Cookie 带不上的场景（内嵌窗口、把链接发给同事）
  也能下载，且仍然要求身份合法；
- 个人端新增 `POST /online/releases/download`：**由程序自己去中心取包**——断点续传 +
  SHA-256 校验 + 解包结构检查（唯一 EXE、`portable.flag`、`使用说明.txt`），存到
  `storage/team_updates/downloads/` 并提示完整路径；配套 `POST /online/releases/reveal`
  一键打开所在文件夹。这条路不依赖浏览器下载子系统，桌面窗口里一定能用；
- 管理员重复上传同一版本号时，改为明确提示"已存在，请下架旧版或改版本号"，
  不再抛 `UNIQUE constraint failed`。
