## 本版修复（注册双流程）

### 1. “管理员注册提示用户已存在”

根因：`admin` 是**首次启动时自动创建**的管理员账号（用户名 `admin`，密码在数据目录的
`HUB_ADMIN_CREDENTIALS.txt`，修改密码后该文件销毁）。用 `admin` 再走注册页必然撞唯一约束。
同时，注册路由把**所有**建号冲突（包括邮箱重复）都笼统报成“用户名已经存在”。

修复：

- 注册时先检测用户名/邮箱冲突，再消耗邀请码；冲突不再扣次。
- 用户名 `admin`：明确提示“这是首次启动自动创建的管理员账号，请直接登录；忘记密码时使用
  `WendaoResearchV3.exe admin-path` 查看凭据文件，无需重新注册”。
- 用户名重复：提示“用户名 XX 已被使用，请换一个”；被停用账号占用会单独说明。
- 邮箱重复：提示“邮箱 XX 已被账号 YY 使用，请换一个邮箱或留空”。
- 注册页顶部说明管理员账号无需注册。

### 2. “成员注册提示邀请码无效”

最常见的外部原因是：**管理员建码的中心实例，和成员注册的中心实例不是同一个**（例如管理员在本地
`/team` 建码，成员打开的是云端或另一台机器的地址）——两边的 `hub.db` 不同，码自然查不到。

修复：

- 每个中心库在首次启动时生成 **8 位中心实例 ID**（`hub_settings.instance_id`），旧库升级后首次启动自动补建。
- 管理员“邀请码”面板显示该 ID；成员注册遇到“邀请码不存在”时，错误信息会带上同一个 ID。
- 两个 ID 不一致 ⇒ 管理员和成员不在同一实例，请让成员使用与管理员面板同源的注册地址。
- 管理员邀请码列表改为**最新生成的排在最前**，避免同秒生成时新旧码顺序混乱。

### 3. 顺带修复：管理页写库导致的 database is locked

排查中发现：把实例 ID 的写入放进管理页（只读请求）会让该连接从 WAL 读快照升级为写时撞锁。
现已改为：实例 ID 在 `init_hub_db` 启动时创建；管理页只读；只有已持有写锁的注册路径才允许惰性补建。
