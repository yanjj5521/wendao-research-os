## 一、修复：福利"额度消失"与材料覆盖不全

根因：管理端福利表单/接口只处理 5 种类型（修为、灵石、灵木、玄铁、星砂）——
填写的其他材料额度被直接丢弃，且中心库 `hub_welfare_grants` 表缺少对应列。

修复：

- 中心库 **v4→v5 迁移**：福利表补齐 全部 8 种缺失材料列
  （修为资产/青灵草/凝露花/赤芝/青锋剑/心镜/乾坤袋/混元石）+ 新增每周额度表；
- 发放表单与接口覆盖 **修为 + 全部 12 种材料**，填写即入账，不再丢；
- 福利历史记录展示同样扩展到全部类型。

## 二、额度全面提高 + 每周自动刷新（随机带下限）

| 类型 | 单次上限（原→新） | 每人每周额度（随机区间） |
| --- | --- | --- |
| 修为（同步） | 60 → **200** | 600–1400 |
| 修为（资产） | — → **100** | 300–700 |
| 灵石 | 50 → **150** | 450–1050 |
| 灵木 | 6 → **20** | 60–140 |
| 青灵草 | — → **30** | 90–210 |
| 凝露花 | — → **20** | 60–140 |
| 赤芝 | — → **10** | 30–70 |
| 青锋剑 | — → **6** | 18–42 |
| 心镜 | — → **6** | 18–42 |
| 乾坤袋 | — → **2** | 6–14 |
| 玄铁 | 6 → **18** | 54–126 |
| 星砂 | 6 → **18** | 54–126 |
| 混元石 | — → **6** | 18–42 |

机制（`hub/db.py::weekly_quotas` / `enforce_welfare_weekly_limits`）：

- 每周一（ISO 周）自动刷新：为每类资源随机生成本周每人额度，**下限 = 单次×3、上限 = 单次×7**，
  下限保证成员每周都有一笔可观的成长资源（快速发展阶段基数）；
- 额度持久化在 `hub_welfare_week_quota`（生成时自持短事务 + 双检，防并发重复）；
- 发放时校验"本周已发 + 本次 > 随机额度"则拒绝，并**明确提示剩余**；
- 替代了旧的每日限额（周刷新是唯一的周期口径，单次上限仍生效）。

## 三、红包功能扩展

- **资产覆盖**：红包支持 修为（资产）与全部 12 种材料（个人红包/群红包均可选）；
- **聊天发红包**：聊天页新增"🧧 发红包"面板——选类型、填总数与份数、写祝福语 →
  托管份额后自动在聊天流发布通知，**所有成员 20 秒内刷新可见**；
- **论坛发红包**：论坛页新增"🧧 发红包帖"——自动发布 `[红包]` 前缀讨论帖 +
  聊天流全员通知；领红包统一到 **同行坊市** 的群红包列表（24 小时未领自动退回）；
- 发出即托管进中心账本，发出方余额不足会在事务内失败，不会出现负资产。
