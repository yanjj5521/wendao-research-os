## 修复：启动报 “ModuleNotFoundError: No module named 'pydantic_core._pydantic_core'”

### 根因

pydantic v2 的核心是**编译扩展**（`pydantic_core._pydantic_core`，一个 `.pyd` 二进制）。
PyInstaller 的自动 hook 在部分版本/环境下会漏收这个二进制，导致打包出的 EXE 一启动就在
`pydantic/version.py` 处报 `ModuleNotFoundError`（后面的“Site initialization is disabled…”
是 PyInstaller 引导器的提示，不是 Python 环境问题）。

### 修复（双保险，均在构建侧）

1. **强制收集**（`packaging/WendaoResearchV3.spec`）：对 `pydantic` 与 `pydantic_core`
   显式 `collect_all`，把纯模块、二进制扩展与元数据全部打进 EXE，不再依赖自动 hook。
2. **构建门禁**（`tools/build.py::verify_executable`）：每次构建完成后自动**冷启动**新 EXE
   执行 `version`，要求退出码 0、输出版本号且不含 `ModuleNotFoundError`；不满足直接终止构建。
   以后任何“缺件只在用户机器上暴露”的打包问题都会在构建阶段被拦下。

### 受影响与不受影响

- 本仓库官方 Release 的 EXE 在发布前都跑过 `version`/`diagnose`，**正常可用**；
  该报错最常见于：自行从源码打包（PyInstaller 版本不同）、或使用了早期/第三方构建的 EXE。
- 无论哪种来源，升级到本版即可获得带门禁保证的构建。

### 用户处置

1. 下载本页 `WendaoResearch-v1.6.1-User.zip`，解压后把 `WendaoResearchV3.exe`
   覆盖到原程序目录（数据目录不受影响）；
2. 若你无法使用应用内更新（EXE 已起不来），**只能手动替换 EXE**，正好下载本包即可；
3. 自行打包的开发者：拉取本版源码后执行 `python tools/build.py --assemble`，
   构建末尾会自动完成冷启动自检。
