## Headscale 部署与维护全面简化（v2 部署资产）

`deploy/headscale/` 全面升级，中心部署从"手工改一串 CHANGE_ME"变成**一条命令**：

```bash
# 推荐：无域名，Let's Encrypt 真证书（sslip.io 服务，无需购买域名）
MODE=sslip SERVER_IP=<你的公网IP> ./deploy.sh
```

脚本自动完成：渲染 config/Caddyfile → 生成证书（selfsigned 模式）→
`docker compose up` → 等待健康检查 → 打印成员接入所需全部信息（控制地址、
CA 导入脚本、预授权密钥命令）。幂等可重复执行，`./data` 数据不受影响。

### 无域名三路径（详见 docs/HEADSCALE.md）

| 路径 | 控制地址 | 证书 | 客户端操作 |
| --- | --- | --- | --- |
| **A. sslip.io（推荐）** | `https://<IP>.sslip.io` | Let's Encrypt 真证书 | 无 |
| **B. IP 自签（纯内网）** | `https://<IP>` | 自建 CA（10 年）+ IP SAN 证书（825 天），headscale 原生 TLS | 导入一次 CA（脚本自动生成 `client-install-ca.ps1`，走 Windows 系统证书库，助手零改动） |
| **C. 自有域名** | 原有方式 | Let's Encrypt | 无 |

### 其他简化

- compose 增加健康检查（`headscale healthcheck`，distroless 镜像可用）与
  `profiles` 分组（Caddy 仅在需要时启动）；镜像版本可经 `HEADSCALE_VERSION` 覆盖；
- 新增 **systemd 裸机托管**：`systemd/wendao-headscale.service`
  （`Restart=on-failure` + `ProtectSystem=strict` 等安全加固）+ 使用说明；
- **配置升级指引**：`docs/HEADSCALE.md` 新增"从 v1 配置升级"章节——
  键位变化表 + 升级步骤 + **关键警告：`server_url` 一旦投入使用不可变更**
  （变更会让所有成员重新登录），升级前先选定路径。
