## 1. 管理员邀请码注册旅程修复（本版重点）

**定位**：管理员在登录状态下打开“打开注册页”并提交注册，**注册其实成功了**——
但提交后程序会把会话**静默切换成新成员**，页面跳到新成员的 `/me`，没有任何提示。
管理员看起来就像“注册不了 / 自己的账号丢了”。

**修复**（`hub/routes/auth.py` + `hub_templates/register.html`）：

- 登录态打开注册页时显示红色警示：
  “当前已登录 洞府主人（管理员）。提交注册将创建新账号并自动切换到该账号；为他人代注册后请退出并重新登录你的账号。”
- 注册成功提示：“账号 xxx 已创建并自动登录；如你是管理员，请退出后重新登录自己的账号。”
- 管理员可随时重新登录 `admin` 找回管理界面（密码即你的管理员密码）。

**成员上限透明化**（`hub/routes/admin.py` + `hub_templates/admin.html` + 新增
`POST /admin/settings`）：邀请码面板显示“成员名额：已用 X / 上限 Y（剩余 Z）”；
管理员可直接调整上限（2–200，动作入审计）。注册满员的错误信息同步更新为
“已达到当前上限（Y）。请管理员在‘管理控制台 → 邀请码’调整成员上限后重试。”
（此前上限满时只报一句“达到上限”，管理员无从下手——这是“注册不了”的另一种常见原因。）

**验证**：`tests/test_admin_register_journey.py` 走完整旅程：管理员建码 → 登录态开注册页（警示可见）
→ 提交 → 成员创建 + 明确提示 → 管理员重新登录 → 收紧上限到 2 后第三人注册给出带入口的错误
→ 上调到 3 后注册立即成功。

## 2. 任务上传系统“错误提交与撤回”设计文档

新增 `docs/designs/upload-withdrawal.md`，覆盖需求五模块 + 异常清单，全部锚定真实代码
（`web/routes/library.py` 的 entries/quests、`services/economy` 的 XP/灵石账本）：

- 用户侧撤回：入口、必填信息、7 类错误枚举与自动处置表、自动化受理状态机；
- 奖励处理：性质/恶意/金额阈值三维判定，自动冲正触发条件，不足转欠账（永不负余额）；
- 自撤回边界：24h/72h 时限、未被审核/引用、频次限制及**设置依据**；越界自动转管理员；
- 管理员流程：通过/驳回/转修订/标记恶意四分支，权限矩阵，快照+冲正单+活动日志三线留痕；
- 迭代修改：`entry_revisions` 版本管理、差异分级审核（>30% 转人工）、修订默认不发奖励、
  防拆分刷分（追加 ≤ 原奖励 50%）；
- 12 项异常矩阵（重复撤回/并发审核/奖励不足/附件丢失/超时升级等）与兜底策略；
- 新表 DDL 草案、路由锚点、发放侧埋点与 M1→M3 分期。
