## 邀请码注册修复（本版重点）

### 根因

`find_invite` 之前把表单里的 `invite` 原样 `strip()` 后与数据库 `code` 做精确比较。实际输入经常不是“裸码”：

1. 用户把**整条注册链接**粘进邀请码框（`.../register?invite=ABC`）；
2. 从聊天里复制成“**邀请码：ABC。**”这样的整句；
3. 全角字符、零宽字符、换行或空格混入；
4. 旧邀请码由 `token_urlsafe(8)` 生成，可能含 `-`、`_` 和混合大小写，手输/转发容易变形；
5. 旧库中可能存在带首尾空格或不可见字符的码，精确匹配查不到。

这些情况都会落到同一个 `missing` 分支，于是统一提示“邀请码无效”，把“格式不对 / 不存在 / 已用完 / 已过期”混在了一起。

### 修复内容

- **先规范化，再查库**（`hub/invites.py`）：
  - NFKC 归一化全角字符；
  - 去除空格、换行、零宽字符与 BOM；
  - 若输入是注册链接，自动提取 `invite=` 参数并 URL 解码；
  - 若输入是整句，自动提取其中最长的合法码片段；
  - 去除引号、括号、中文标点。
- **格式校验**：合法码为 6–64 位 `A-Z a-z 0-9 _ -`；格式不对单独提示，不再报“无效”。
- **查库兼容旧数据**：
  - 先按 `TRIM(code) = ? COLLATE NOCASE` 查；
  - 查不到时对小型邀请码表做一次规范化扫描，兼容旧码中的空格/不可见字符；
  - 扣次仍使用数据库中的原始 `code`，保证能命中旧行。
- **新码生成更安全**（`generate_invite_code`）：
  - 10 位大写字母/数字；
  - 去掉易混的 `I/O/0/1`，不再使用 `-`、`_`；
  - 管理员建码与首次建库种子码都改用该函数；**旧码仍然有效**。
- **错误提示分型**：
  - 格式不正确：提示粘贴完整邀请码或注册链接；
  - 不存在或已失效：提示让管理员重新生成；
  - 已用完 / 已过期：分别提示。
- **表单体验**：注册页提示可直接粘贴注册链接；关闭自动完成/拼写检查；注册页入参会先规范化，避免超长链接显示在输入框里。
- 管理员邀请码面板增加说明：新码 10 位、旧码有效、可直接用注册链接。

## 实际注册流程验证

- 管理员登录 → 生成 5 次邀请码 → 分别用以下四种输入注册：
  1. 裸码；
  2. 全小写；
  3. 整条注册链接；
  4. `邀请码：CODE。` 整句。
- 四种方式全部 303 → `/me`，账号创建成功；剩余次数从 5 正确扣到 1。
- `ABC`（过短）→ “格式不正确”；
- `ZZZZZZ`（格式合法但不存在）→ “不存在或已失效”；
- 一次性码第二次使用 → “已用完”。
- 自动化：`tests/test_hub_registration.py` 覆盖同一流程；`tests/test_hub_invites.py` 18 项覆盖规范化、全角、零宽、旧码空格、原子扣次。
