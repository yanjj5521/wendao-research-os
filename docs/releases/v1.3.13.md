## 本版新增

### 群红包（多人抢）

- 坊市新增“发群红包”：总数量 2–20 份，24 小时内可抢，发出时先从发送者账户扣除总额。
- 抢包规则：
  - 每人每个红包只能抢一次，发送者不能抢自己的红包；
  - 每份金额随机，最多为当前平均值的 2 倍，且为后续每份预留至少 1；
  - 最后一份拿走剩余全部，总额精确分配，不会出现 0 或负数；
  - 抢完自动 `finished`；24 小时未抢完自动 `expired`，剩余原额退回发送者。
- 并发安全：创建与抢包都在 `BEGIN IMMEDIATE` 事务内完成，重复/并发抢包不会超发。
- 数据表：`hub_red_packets`（红包）与 `hub_red_packet_claims`（领取记录），旧库启动时自动补建。

### 聊天消息即时呈现

- 发送时先在界面插入“发送中”气泡，**不等服务器返回就已显示**；服务器确认后原地替换为正式消息。
- 新增 `POST /chat/send.json` 与 `GET /chat/messages.json?after=`：
  - 发送走 JSON，不再整页跳转；
  - 页面每 **2 秒**增量拉取新消息，只追加新增项，不重载页面。
- 预期延迟：自己发送的消息在本地一帧内出现；其他成员的消息最多约 2 秒出现（取决于轮询时刻）。
- 无 JavaScript 时仍回退到原来的表单 POST + 整页刷新。
- 滚动策略：只有停留在底部时才自动滚到新消息，阅读旧消息不会被打断。

### 论文/资料卡低优先级

- 聊天页标记 `data-priority="chat-immediate"`，不查询论文或资料卡数据。
- 资料驿站标记 `data-priority="paper-deferred"`，资料卡使用 `content-visibility:auto`：
  - 首屏只渲染可见卡片，屏幕外的论文卡片延迟到进入视口时再渲染；
  - 资料页不参与聊天轮询，不会与聊天争抢刷新通道。
- 这是**渲染优先级**的保证，不是独立的网络调度器：论文仍会在打开资料页时请求，但不会阻塞聊天。
