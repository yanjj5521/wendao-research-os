## 一、GitHub 下载不了：这次定位到具体环节

实测（本机）：发布页与资产在浏览器/`curl` 下 200，但**应用内下载卡死**。分步复现后确认：

- `api.github.com`（取版本信息）正常，**1.3 秒返回**；
- `github.com/.../releases/download/...`（取资产）在无代理时超时；
- 而且原来的 SHA-256 来自同一域名下的 `SHA256SUMS.txt`——**下载地址不通时，校验文件也一起拿不到**，于是直接失败。

修复三件事：

1. **哈希改从 API 取**：GitHub Releases API 已经返回资产的 `digest`（`sha256:...`），优先用它；
   只有 API 没给时才回退到 `SHA256SUMS.txt`；
2. **代理可配**：设置 → 版本更新新增「GitHub 下载代理」，填一次即对查询与下载同时生效；
3. **镜像回退**：直连失败后自动尝试 `ghproxy.net`、`gh-proxy.com` 两个通道，
   每个通道下载完都要过同一个 SHA-256 校验——镜像只负责传输，不能改变内容。

实测结果：配置代理后 **6.1 秒**下完 73 MB 用户包，摘要与本地 `SHA256SUMS.txt` 完全一致。

## 二、管理员上传 → 用户安装：全链路重新验证

新增端到端测试 `tests/test_release_e2e.py`，不是模拟，而是：

1. 管理员在管理台**真实上传** `Team-Update.zip`（含结构校验与重复版本拦截）；
2. 起一个真实 HTTP 中心（uvicorn，随机端口），成员端按 URL 取包；
3. 成员端下载 → 校验 SHA-256 与中心记录一致 → 用自动更新同一套 `validate_package` 检查结构；
4. 中心端 `/releases/{id}/download` 入口同时可用。

结论：上传、分发、下载、校验四段都通。

## 三、完整 39 阶境界名同步到中心

之前中心只能按 6 档换算显示，成员自定义的阶名（例如「金丹三层」）带不过去。

- 个人端新增 **同步境界到中心**（联机页按钮）：只推 `realm_name / realm_index / cultivation` 三项快照；
- 中心端新增 `POST /api/v1/profile/realm`（Bearer 鉴权），写进账号 `metadata_json`；
- 展示优先级：**个人端快照 → 中心 6 档换算**，成员页、首页、我的主页、管理台一致；
- 只读快照，不回写、不影响权限与额度。

## 四、论文工作台：PDF 辅助抽取（默认折叠）

按上一轮约定做成「辅助但默认关闭」：

- 只抽 **标题、图表标题（Figure/Table/Scheme）、结论摘录**，不摘要、不翻译、不评价；
- 抽到的每项都有「填入标题 / 填入 Context / 填入主要结果」按钮，填不填由你决定；
- 扫描件（无文本层）直接说明「需要手动填写」，不做 OCR；
- 上限 25 MB / 40 页，避免拖垮界面。
