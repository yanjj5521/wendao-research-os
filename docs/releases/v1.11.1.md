## 一、版本包：管理员与成员都能拿到安装包

1.11.0 的取包按钮还有一个前提没被满足：它读的是**同步缓存**里的 `latest_release`。
管理员自己开中心、不同步到任何地方，缓存永远是空的；成员没同步过同样看不到按钮。
于是"能不能下载"取决于有没有同步过，而不是取决于有没有包。

**现在的规则**（新增 `services/release_feed.py`，按身份现取，不再依赖缓存）：

| 身份 | 版本包信息从哪来 | 取包动作 |
| --- | --- | --- |
| 中心（host） | 直接读本机中心库 `hub_releases` | 本地复制到 `storage/team_updates/downloads/` 并校验 SHA-256 |
| 成员（member） | 向对方中心 `GET /api/v1/releases/latest`（Bearer Token） | 断点续传拉取 + SHA-256 + 解包结构检查 |
| 断网 / 对方不可达 | 退回同步缓存，界面明确标注"来源：上次同步缓存" | 会失败并给出原因，不再假装有包 |

配套改动：

- 界面明确写出包来自哪里：`来源：本机中心` / `来源：http://…` / `来源：上次同步缓存`；
- 没有包时按身份给不同指引：管理员去「版本中心」上传，成员检查地址与 Token；
- 管理员点「更新到中心最新版」会被拦住并说明"你当前就是中心，用下载版本包即可"，
  避免自己从自己那里拉更新；
- 中心端「版本中心」页面补充说明：桌面内嵌窗口下载无反应时，回到个人端的取包按钮；
- 下载文件统一落到 `storage/team_updates/downloads/`，配「打开版本包所在文件夹」。

## 二、按钮写明"要打开哪个中心"，避免误触

- 入口按钮直接带地址：`打开我连接的同行会（192.168.50.20:5050）`、
  `进入我的同行会中心（127.0.0.1:5050）`；未启动时写 `进入本机中心（尚未启动）`；
- 身份卡片里补一句"点之前先看地址：按钮上的地址就是你即将进入的那一份"；
- 成员身份额外给一条 `不是我连的中心？去改连接`，直接跳到连接表单；
- `/team` 的成员说明页同样把地址写进按钮文案。

## 三、找新版本可直接去发布页

- 「更新与同步」新增 **打开发布页（GitHub）**，无论是否检查过都能点，直达
  `https://github.com/yanjj5521/wendao-research-os/releases`；
- 检查到新版本后，额外出现 **查看 vX 发布说明**，直接打开该版本的 Release 页面。
