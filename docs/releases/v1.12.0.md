## 一、修掉"管理员发不出福利"

两个真实缺陷叠在一起：

1. **老库缺列**：1.10.0 把建表语句写成了 13 个福利列，但中心库版本从 v4 跳到 v5 时
   **没有对应迁移**。老库的 `hub_welfare_grants` 只有最初 5 列，管理员一发放就报
   `no column named cultivation`，界面上只看到"福利未发放"。
   → 新增 `HUB_MIGRATIONS` v5：按实际列名增量补 8 列 + 建周额度表，幂等可重复执行。
2. **修为（资产）字段根本没接收**：表单里有这一栏，路由签名里没有 `cultivation`，
   填了也永远是 0。
   → 补齐参数并写入。

顺带修正两处会让额度判错的逻辑：

- 周额度校验原来只取**一条**发放记录，一周发多次时"已用"永远只算一次；
  现在按周求和；
- 请求 0 的数量时不再被"剩余不足"误拦。

## 二、每周福利额度改为"境界 × 人数"

不再是所有人统一的随机区间，而是按中心主人的修行深度与团队规模计算：

```
每人每周额度 = 基准随机区间(单次×3 ～ 单次×7) × 境界系数 × 人数系数
```

| 管理员累计修为 | 境界 | 系数 |
| --- | --- | --- |
| 0 | 练气 | 1.00 |
| 300 | 筑基 | 1.12 |
| 900 | 金丹 | 1.25 |
| 2200 | 元婴 | 1.40 |
| 5000 | 化神 | 1.55 |
| 10000 | 炼虚 | 1.70 |

人数系数 = `1 + min(0.5, (成员数-1) × 0.05)`，即最多 +50%，避免"人一多就无限发"。
生成额度时把两个系数与成员数一并写进当周记录，管理台直接显示
「管理员境界 化神（×1.55）× 成员 8 人（×1.35）」——额度为什么是这个数，一眼能对上。

## 三、跨网络直连：从六个字段变成一个按钮

- 新增 **一键自动组网**：按当前身份自动选中心/成员模式，节点名自动生成
  （`wendao-center-<主机名>` / `wendao-member-<主机名>`），复用已保存的控制端与预授权密钥；
- 成员缺中心虚拟 IP 时，明确提示"向管理员索取后填入"，不再抛底层错误；
- 成功后写入 `headnet_auto`，**下次启动自动恢复**（后台线程，失败静默，不阻塞窗口）；
- 已有连接不会重复接入。

## 四、修仙百艺：炼丹师 / 炼器师 / 御兽师 + 六阶

新增 `services/professions.py` 与新页面 `/professions`（侧栏「成长与陪伴 → 修仙百艺」）：

| 职业 | 经验来源 | 加成作用 |
| --- | --- | --- |
| 炼丹师 | 炼丹成功 +12，失败 +4 | 成丹率、双枚概率 |
| 炼器师 | 淬炼成功 +10，失败 +4 | 淬炼成功率 |
| 御兽师 | 灵兽结契 +15 | 结契成功率 |

六阶：初学(0) → 入门(120) → 精熟(360) → 大家(900) → 宗师(2100) → 天工(4800)，
每阶 +8% 加成（天工 1.40）。经验存 `settings.profession_exp`，不改数据库结构，
升级不会丢进度；三个职业各自累积，"设为主修"只影响展示重点。

## 五、炼丹与炼器不再是"点一下必成"

- 炼丹：基础成丹率 78%，随炼丹师等阶提升（最高 98%）。失败**只烧一半灵草**并 +4 熟练度；
  高阶有概率**丹成双枚**；
- 炼器：基础淬炼成功率 66%，失败扣一半灵石、等级不降、+4 熟练度；
- 两处都在提示里写出本次成功率与熟练度变化，失败原因不再是一个"没反应"。

## 六、宠物乐园 → 灵兽园

按修仙体系重做命名与文案：宠物→**灵兽**、捕捉→**结契**、队伍→**灵兽袋**、
图鉴→**灵兽谱**、精灵球→**灵契球**（契灵球/上品/极品）。存档结构与字段完全不变，
老存档直接可用；御兽师的经验正是从结契里来。

## 七、版本包：中心身份改为"原地定位"

管理员在自己机器上取包不再复制第二份：直接在资源管理器中**定位并选中**
`storage/hub_releases` 里的原文件；成员身份仍走服务端下载 + SHA-256 + 解包结构校验。
