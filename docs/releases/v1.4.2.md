## 本版修复（GitHub 更新提示“更新失败”）

### 根因

1. **读超时不是 URLError**：`_open()` 只捕获 `HTTPError/URLError`，而 GitHub 连接**读超时抛出的是
   `TimeoutError`（OSError 子类）**。实测真实网络下 `SHA256SUMS.txt` 查询直接抛出裸 `TimeoutError`，
   绕过全部友好提示：检查更新变成 500，应用更新变成“GitHub 更新未启动：[Errno …]”。
2. **应用更新前重新请求 GitHub API**：`github-apply` 每次都再查一次 `releases/latest`；刚才“检查”能成功，
   30 秒后“应用”却可能超时或被限流（403），用户手里明明已经有一份校验过的发布信息。
3. **下载已完成后失败不会复用成果**：替换脚本失败后，本地已校验的完整 ZIP 被无视，重试时重新下载 60 MB，
   在不稳定网络下反复暴露在超时风险里。
4. **替换失败对用户不可见**：PowerShell 替换脚本的失败只写在 `apply_update.log`，界面无提示，
   用户只看到“程序又变回旧版本”，无法知道原因（如“新版本启动即退出”）。

### 修复内容

- `_open()`：捕获 `TimeoutError/URLError/OSError`，**自动重试一次**，最终转换为用户可读的
  “无法连接 GitHub（网络超时或不稳定）…”。
- `latest_release()` / `_checksums()`：读取响应阶段的中断/坏 JSON 也转换为友好错误。
- 新增 `resolve_apply_release()`：**“应用更新”优先使用检查时缓存的发布信息**（含版本、包地址），
  缓存不可用时才回退到 API；避免刚检查完就因网络抖动失败。
- `prepare_github_update()`：本地已存在**哈希匹配**的完整更新包时直接复用，不再重复下载；
  哈希不匹配才重新下载。
- `fetch_resumable()`：`RemoteDisconnected` 等**裸 OSError** 统一处理为“下载中断（网络超时或不稳定），
  已保留进度，可重试续传”，并在同一函数内**自动重试一次**（断点续传状态自动校正）。
- PowerShell 替换脚本：EXE 复制增加 **3 次重试**（每次 1 秒），复制失败写明日志后回滚。
- 在线页新增“上次自动替换日志”折叠区：替换失败的**真实原因**（如“新版本启动即退出”）直接可见。
