## 二、文案风格规则

1. **实体名跟随导航标签**：页面 `<h1>` 优先用 `{{ nav_labels.xxx }}`，不要硬编码中文名（用户可改名）。
2. **提示与功能一致**：数字类提示必须与代码常量一致——首页固定上限 6、上传上限 1 GiB、复盘素材 4/12 份、雷劫均分 ≥70、登录限流 8 次/10 分钟。
3. **一句提示只说一件事**：删掉形容词堆叠；"不阻塞本地科研流程"优于"绝对不会影响您的任何宝贵工作"。
4. **按钮用动词**：「确认交付并结算」「保存并联机」「生成图片汇报 PPT」；避免「确定」「提交」这类无信息按钮。
5. **中文与英文眉标并存**：眉标（eyebrow）是装饰性英文小标签，必须与页面主题对应（如领域页用 `… Domain`）。
6. **不写绝对承诺**：涉及 AI、联网、同步的提示必须保留"可能失败"的表述（离线回退、退避重试、断网排队）。

## 三、主要改动点（本次审查）

### 3.1 术语统一（工作区 → 领域，14 个文件）

- 表单标签：`工作区名称/类型/（可选）/所属工作区/放入工作区/关联工作区` → 对应「领域」表述（assistant、cultivation、datasets、editor、experiments、plans、project、projects、simulations、upload、workspaces）。
- 按钮与入口：`管理工作区` → `管理领域`；`新建工作区` → `新建领域`；`打开工作区` → `打开领域`。
- 计划协议示例与导出文本：`工作区：EG 实验` → `领域：EG 实验`（解析器本就同时接受「工作区/领域」两种键，导入不受影响）。
- 个性化包说明：`工作区目标、流程与组件` → `领域目标、流程与组件`。
- 领域页眉标：`… Workspace` → `… Domain`（workspace_profiles.py 九个 kicker + datasets/experiments/simulations 模板）。

### 3.2 术语统一（课题 → 项目，11 个文件）

- 表单与按钮：`课题名称` → `项目名称`；`建立课题并查找先例` → `建立项目并查找先例`；`保存课题定义` → `保存项目定义`；`关联课题` → `关联项目`。
- 页面标题：`课题推进` → 跟随导航标签 `{{ nav_labels.projects }}`；`· 课题推进` → `· 项目`。
- 计划协议示例与导出文本：`课题：…` → `项目：…`。
- 上下文标签：`课题 · …` → `项目 · …`（今日学习、近期计划）。
- AI 协作台：`全部推进中课题` → `全部推进中项目`；保存目的地 `课题推进` → `项目推进`。

### 3.3 提示与定位统一

- 首页弱化链接：`科研课题` → `项目`（与侧栏一致）。
- 成就页：`你的科研成长星图` → `你的成长星图`。
- 个人主页：`科研资产` → `知识资产`；道心占位 `科研成果` → `学习与研究成果`。
- 写笔记页：`写一条科研笔记` → `写一条笔记`。
- 领域页占位：`科研专题空间` → `专题学习空间`。
- 设置页备份卡片：`个人工作区…科研空间` → `学习领域…学习方向`。
- 秘境试炼：`开始科研前热身` → `开始学习前热身`（该页其余"科研判断"为真实研究语境，保留）。

### 3.4 结构修正

- `projects.html` 的 `<h1>` 原为硬编码「课题推进」，改为 `{{ nav_labels.projects }}`——用户改导航名后页面标题会跟着变。
- `project.html` 表单 `课题状态` → `项目状态`；`project_plan.html` 返回按钮 → `返回项目`。
- `plan_import.py` 导出文本同步改键（解析兼容旧文本，历史导出的计划仍可重新导入）。

### 3.5 明确不改的

- foundation 子系统页面文案（交付文件夹的活后端，术语沿用旧版，避免误导路径排查）。
- hub_templates（同行会中心）：`hub_*` 表名与中心文案自成体系，账号模型刚重建，等中心界面专项审查时统一。
- 趣味层文案（炼丹、洞府、彩蛋）：叙事自成一体，仅修明确错误。
