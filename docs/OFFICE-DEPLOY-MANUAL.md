# 同办公室混合组网 · 零基础操作手册

> 场景：同一个办公室，但同事之间**不在同一个局域网**（不同网段/不同路由器，甚至互相
> ping 不通）。方案是两条轨道并用：
>
> - **轨道一 · 局域网直连**：能直接互访的同事走局域网地址，5 分钟搞定；
> - **轨道二 · Headscale 虚拟网**：跨网段/被隔离的同事走虚拟网，约 30 分钟；
> - 两条轨道**同时生效、互不冲突**：程序会同时列出局域网入口和虚拟网入口，
>   每个成员按自己的连通情况选一条用即可。
>
> 全程不需要公网 IP、不需要购买域名、不需要云服务器。
> 本手册假设你从未接触过服务器/命令行——每一步都写了"点哪里、敲什么、看到什么算成功"。

---

## 第 0 章 · 先花 5 分钟做"连通性自测"（决定你走哪条轨道）

在**另一台同事的电脑**上（不是你自己的）：

1. 按 `Win + R`，输入 `cmd`，回车，打开黑色命令行窗口；
2. 输入 `ping <你的电脑IP>` 后回车（你的电脑 IP 的查看方法见下方"怎么查我的 IP"）；
3. 看结果：
   - 出现 4 行 `来自 192.168.x.x 的回复: 字节=32 时间=1ms` → **互通**，这位同事走
     **轨道一**就够了；
   - 出现 `请求超时` 或 `无法访问目标主机` → **不通**，这位同事需要走 **轨道二**。

> **怎么查你的电脑 IP**：`Win + R` → 输入 `cmd` → 输入 `ipconfig` → 找
> "无线局域网适配器 WLAN"或"以太网适配器"下面的 `IPv4 地址`（形如 `192.168.1.20`）。
> 如果程序已经启动过中心，同行会页会直接列出所有入口，不用手工查。

把结果记下来：**同网段同事名单** → 轨道一；**不通的同事名单** → 轨道二。
两条轨道做完后，所有人都能用。

## 第 1 章 · 轨道一：局域网直连（5 分钟）

### 1.1 你（管理员）的操作

| 步骤 | 操作 | 成功的样子 |
| --- | --- | --- |
| 1 | 双击 `WendaoResearchV3.exe`，打开**同行会**页 | 看到同行会主页 |
| 2 | 点击 **"启动本机同行会中心"** | 面板显示 **运行中**，并列出 1~3 条入口（有线/无线分类） |
| 3 | 首次启动 Windows 弹出防火墙提示 → **勾选"专用网络"→ 点"允许访问"** | 弹窗消失，入口列表正常 |
| 4 | 管理控制台 → **邀请码** → 生成 → 点 **"打开注册页"** → 复制完整链接 | 链接形如 `http://192.168.x.x:5050/register?invite=XXXX` |

把链接发给 **同网段** 的同事（第 0 章里 ping 通的那些）。

> 如果之前点过"取消"导致弹窗不再出现：管理员 PowerShell 执行
> `netsh advfirewall firewall add rule name="WendaoResearch" dir=in action=allow program="<EXE完整路径>" enable=yes`

### 1.2 同网段同事的操作

| 步骤 | 操作 | 成功的样子 |
| --- | --- | --- |
| 1 | 解压同版本 `…-User.zip`，双击 `WendaoResearchV3.exe` | 打开程序 |
| 2 | 打开**同行会**页 → 粘贴管理员发的链接 → 注册 → 登录 | 进入论坛/资料卡界面 |

详细说明与故障排查见 `docs/LAN-DEPLOY.md`。

## 第 2 章 · 轨道二：Headscale 虚拟网（跨网段，约 30 分钟）

### 2.0 先想清楚：控制端装在哪台机器上

Headscale 控制端必须**被所有需要跨网段访问的电脑访问到**。按顺序考虑：

1. **办公室的 NAS**（群晖/威联通等能装 Docker 的）——首选；
2. **接在主路由（总交换机）下的任何一台常开电脑**——通常所有网段都能访问它；
3. 管理员自己的电脑——**仅当**跨网段同事能 ping 通它时可行（ping 不通则它当控制端没意义）。

> 判定方法：在**不通网段的同事电脑**上 `ping <候选机器IP>`，能通的那台就是控制端。
> 如果所有候选都不通，说明网段之间完全隔离，需要网管在路由器上加一条静态路由
> （把各网段路由到主路由），或者干脆全部改走轨道一 + 网管放行——这超出了纯软件能解决的范围。

下文假设控制端是一台装了 Docker 的 NAS/电脑，IP 记为 `<控制端IP>`。

### 2.1 部署控制端（一条命令）

把仓库里 `deploy/headscale/` 整个文件夹复制到控制端机器，进入该目录执行：

```bash
MODE=selfsigned SERVER_IP=<控制端IP> ./deploy.sh
```

| 你会看到 | 含义 |
| --- | --- |
| `==> 模式：selfsigned · server_url = https://<控制端IP>` | 已选定纯内网自签模式 |
| `==> 生成根 CA（10 年）…` | 自动生成证书（不用管） |
| `==> 等待健康检查…` | 容器正在启动 |
| `==> 部署完成。下一步：` | **成功**，按屏幕提示继续 |

### 2.2 创建用户和每个人的"预授权密钥"

在控制端机器上执行（`张三` 换成每个人的名字，一人一条）：

```bash
docker exec wendao-headscale headscale users create 张三
docker exec wendao-headscale headscale preauthkeys create --user 张三 --reusable --expiration 24h
```

输出的 `preauth key`（形如 `1c3f…`）发给对应的人。**只显示一次**，别发到公开群。

### 2.3 你（管理员）：导入 CA + 在程序里"作为中心启动"

| 步骤 | 操作 | 成功的样子 |
| --- | --- | --- |
| 1 | 把控制端 `client/wendao-headnet-ca.crt` 拷到自己电脑，右键 → **安装证书** → 本地计算机 → 受信任的根证书颁发机构 | 导入成功提示（每台电脑一次） |
| 2 | 同行会页 → **Headscale 虚拟专网** → 控制端地址填 `https://<控制端IP>`，预授权密钥填**你自己那条**，节点名称填 `wendao-hub` | 表单填好 |
| 3 | 点 **"作为中心启动"** | 页面显示中心虚拟地址，形如 `http://100.64.0.1:5050` |

**记下这个 `100.64.x.x` 虚拟地址**——这就是跨网段同事要用的入口。

### 2.4 跨网段同事：导入 CA + "作为成员连接"

| 步骤 | 操作 | 成功的样子 |
| --- | --- | --- |
| 1 | 同样导入 `wendao-headnet-ca.crt`（每台一次） | 导入成功 |
| 2 | 同行会页 → Headscale 虚拟专网 → 控制端地址同上，预授权密钥填**自己那条**，**中心虚拟 IP** 填管理员的 `100.64.x.x` | 表单填好 |
| 3 | 点 **"作为成员连接"** | 显示本地代理入口，形如 `http://127.0.0.1:xxxx` |
| 4 | 同行会页此时相当于已经"打开中心"——注册/登录走这个入口即可 | 进入论坛/资料卡 |

> 原理：成员程序在本机 `127.0.0.1` 开一个代理，通过虚拟网把请求转发到你电脑上的
> 同行会中心。数据仍然全部保存在你的电脑上。

## 第 3 章 · 组合使用：谁用哪个入口

| 同事 | 用的入口 | 填写方式 |
| --- | --- | --- |
| 与你同网段（ping 通你） | `http://<你的局域网IP>:5050` | 用轨道一的注册链接 |
| 跨网段（ping 不通你，但能通控制端） | headnet 本地代理入口 | 轨道二流程，虚拟 IP 填你的 |
| 两种都能通 | 随便选；**优先局域网**（更快，不依赖控制端在线） | — |

程序会同时列出两类入口，成员页可以看到"有线局域网 / 无线局域网 / VPN/虚拟局域网"
的分类标签，不用记。

## 第 4 章 · 日常维护（每周 1 分钟）

| 事项 | 做法 |
| --- | --- |
| 每天开机 | 双击 EXE → 启动本机同行会中心 → （轨道二）Headscale 面板"作为中心启动"。想全自动：把 EXE 快捷方式放进 `Win+R` → `shell:startup` |
| 控制端开机自启 | Docker 模式已内置 `restart: unless-stopped`，NAS/电脑开机即自动运行 |
| 固定你的 IP | 路由器 DHCP 静态绑定；固定后成员永不改地址 |
| 数据备份 | 管理控制台 → 备份。**你电脑 = 全团队数据库**，建议每周一次 |
| 程序升级 | 先升级成员，最后升级中心；应用内更新（自带断点续传+校验） |

## 第 5 章 · 故障排查速查

| 现象 | 先检查 | 再检查 |
| --- | --- | --- |
| 局域网同事打不开页面 | 中心是否"运行中" | 防火墙规则（第 1 章命令）；`ping` 连通性 |
| 轨道二成员报 TLS/x509 错误 | 是否导入过 CA（受信任的根证书颁发机构里找 "Wendao Headnet CA"） | 控制端地址是否一字不差 `https://<控制端IP>` |
| headnet 启动后一直转圈 | 预授权密钥是否过期（24h） | 控制端容器是否 healthy：`docker ps` |
| 虚拟地址打不开 | 管理员电脑上中心是否"运行中"；headnet 中心端是否还活着（面板显示） | 控制端 DERP：`docker logs wendao-headscale` |
| 昨天还能连今天不行 | 你的 IP 变了？（`ipconfig` 对照入口列表） | 控制端 IP 变了？（同样固定 IP） |

## 附录 B · 术语一句话

| 词 | 意思 |
| --- | --- |
| 局域网 / 网段 | 一个路由器下面的设备群；`192.168.1.x` 和 `192.168.31.x` 属于不同网段 |
| 预授权密钥 | 加入虚拟网的"一次性门票"，由管理员生成、每人一条、有有效期 |
| 控制端（Headscale） | 给所有虚拟网节点"发牌"的中心服务，装在 NAS 或某台常开电脑上 |
| 虚拟地址 `100.64.x.x` | 加入虚拟网后每台电脑获得的"内部门牌号"，跨网段互访全靠它 |
| CA / 导入证书 | 自签名模式下，让成员电脑"信任"服务器的一张凭证；每台导入一次 |
