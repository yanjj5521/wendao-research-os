# 科研系统 1.0 收敛方案

> 版本：3.6.x → **1.0.0**
> 目标：把「功能实验场」收敛成「能连续使用半年以上的科研工作流系统」。
> 判断标准只有一条：**它是否让科研闭环更短、更可查、更少选择**。

---

## 一、先承认现状

| 指标 | 3.6.1 现状 |
| --- | --- |
| 页面模板 | 38 个 |
| 路由 | 150 条（个人端） |
| 数据表 | 38 张 |
| 侧栏默认可见 | 13 项，分 6 组 |
| 默认学习领域 | 7 个，其中 6 个固定在首页 |

这不是缺陷清单，而是事实：**入口数量已经超过一个人每天的决策预算**。3.6.x 的每个版本都在加能力，但没有一个版本回答"哪些应该消失"。

---

## 二、五个问题，五个界面

1.0 的界面数量由问题数量决定，而不是由功能数量决定。

| # | 问题 | 界面 | 数据来源 | 默认可见 |
| --- | --- | --- | --- | --- |
| ① | 今天打开它干什么？ | 主页 + 今日学习 | `study_plans` / `daily_missions` | 是 |
| ② | 这周真正完成了什么？ | 温故知新（周复盘） | `mission_deliveries` / `review_sources` | 是 |
| ③ | 科研任务如何留下证据？ | 交付（内嵌在①的结算动作里） | `storage/deliveries/` + `mission_delivery_files` | 不单独设页 |
| ④ | 文献→思考→实验→数据→论文如何串？ | 项目页的**证据链** | `entries` / `experiments` / `simulations` / `career_moments` | 是 |
| ⑤ | 哪些功能没人用？ | 见第五节（用数据流向判断，不靠感觉） | — | — |

**③ 不单独做页面**，这是 1.0 最重要的减法：证据不是"一个功能"，而是完成任务时的一个必填动作。任何把它做成独立页面的设计，都会变成第二个待办清单。

---

## 三、闭环与数据对应

```text
                 ┌── 学习（今日/计划）
                 ├── 文献（精读 → 条目）
                 └── 项目（课题容器）
                          │
                          ▼
                        思考（笔记/问题/失败复盘 → entries）
                          │
                          ▼
                        实验（experiments 台账）
                          │
                          ▼
                        数据（dataset 条目 + 分析脚本）
                          │
                          ▼
                        分析（simulations / 代码条目）
                          │
                          ▼
                      阶段成果（闸门 passed + 成果节点）
                          │
                          ▼
                  论文 / 汇报 / 项目（交付 + 文献汇报 PPT）
                          │
                          ▼
                    新的科研任务（推进记录 → 下一行动）
```

每一环在 1.0 里都必须**可点、可数、可空**：空环要显式提示"这一环还没有材料"，而不是让人以为自己已经完整。

这张图取代了原来的"课题优先"叙事：项目不再是一个需要天天推进的对象，而是**证据链的容器**。这也解释了两版定位的差异——上一版把项目降为附带记录，是因为它被当成了组织轴；1.0 把项目请回主干，是因为它承担"串联"职责，而不是"打卡"职责。

## 四、功能存活判断（六个月尺度）

判断依据不是喜好，而是**数据流向**：一个功能如果只写不读、或写下的数据没有任何下游消费方，它在半年后必然被绕过。

### 4.1 保留（有下游消费方，或被每日动作依赖）

| 功能 | 为什么活下来 | 下游消费方 |
| --- | --- | --- |
| 今日学习 / 每日任务 | 唯一产生"当天交付"的入口 | 交付目录 → 复盘题库 |
| 近期计划 | 提供 3–7 天的任务骨架 | 每日任务 |
| 温故知新 | 消费交付文本，产出到期节奏 | 复习调度、雷劫 |
| 文献精读 | 把 PDF 变成条目 + 关键图 | 知识库、汇报 PPT |
| 知识库 | 一切条目的落地处 | 检索、导出、项目证据链 |
| 项目（课题） | 证据链容器 + 闸门 | 证据链、阶段成果 |
| 交付 | 证据的物理形态 | 复盘、知识卡、备份 |
| 数据备份 | 半年尺度上唯一不可省 | 恢复 |
| 学习领域 | 多方向并行的容器 | 全部记录归属 |
| 掌握度/复盘自评 | 决定下次到期 | 复习调度 |

### 4.2 降级为"按需打开"（保留代码，退出默认路径）

| 功能 | 处理 | 理由 |
| --- | --- | --- |
| 实用工作台（润色/图表） | 从侧栏移除，保留首页入口 | 每周用一次，不需要每天看见 |
| 全库检索 | 从侧栏移除 | 首页双检索已覆盖 |
| 写笔记 / 上传 | 从侧栏移除 | 知识库内已有同等入口 |
| 联网找论文 | 从侧栏移除 | 首页检索第二个按钮已覆盖 |
| 闭关计时 | 从侧栏移除 | 低频，且可用系统计时器替代 |
| 成长罗盘 | 从侧栏移除 | 月度回看，不是每日动作 |
| 学习领域快捷入口 | 收起，保留"领域管理"一项 | 7 个领域平铺会挤占主线 |

### 4.3 收进"趣味层"开关（默认关闭）

这些功能**不产生任何科研产物**，只产生情绪价值。它们不是坏设计，但不该占据 1.0 的主界面。

| 功能 | 数据表 | 有无下游 |
| --- | --- | --- |
| 炼丹炉 | `special_tasks` / `herb_inventory` / `inventory_items` | 无（丹药只加修为） |
| 我的洞府（法器/建筑/彩蛋） | `inventory_items` / `asset_transactions` / `easter_eggs` | 无 |
| 成就图鉴 | 运行时计算 | 无 |
| 挂机静修 | 壁纸设置 | 无 |

**保留** 秘境试炼：它不是装饰，是间隔练习的入口（灵光问答/因果迷宫/反证之境/万象秘境），有真实的复习调度价值。
**保留** 修为与境界：它是长期进度条，不是货币。灵石随趣味层一起隐藏。

### 4.4 合并 / 不再单独暴露

| 原功能 | 归入 |
| --- | --- |
| 交付文件夹 | 知识库附件 |
| 文献汇报 PPT | 文献精读的产出动作 |
| 阶段成果 | 项目页证据链的最后一环 |
| 生涯节点 | 项目推进记录 + 成长罗盘（按需） |

### 4.5 明确不做（1.0 的非目标）

- 不做多用户协作的实时编辑（同行会只做轻量状态）；
- 不做自动扫描本地文件；
- 不做向量库/语义搜索（FTS5 够用）；
- 不做移动端原生重写；
- 不加新的游戏系统；
- 不为"看起来完整"而保留空壳页面。

## 五、⑤ 怎么用数据回答，而不是靠感觉

本次收敛用的是**静态数据流审计**：统计每张表的写入方与读取方，只写不读的表对应的功能优先降级。它有一个明显局限——**无法知道你是否真的在用**。

因此 1.0 只做一件事为后续铺路：**在 `activities` 里记录页面访问**（已有表，不加表结构），1.1 再用真实的 30 天访问分布做第二轮裁剪。

在拿到真实数据前，任何"这个功能没人用"的判断都只是设计推断，不应据此删除代码——所以本版的处置一律是**隐藏而非删除**，随时可在设置里找回。

## 六、1.0 的默认界面（最终形态）

```text
学习主线      主页 · 今日学习 · 近期计划 · 温故知新 · 文献精读
积累与输出    知识库
学习领域      领域管理
研究与课题    项目
协作与系统    设置
```

共 **9 个入口、5 个分组**（3.6.1 是 13 个入口、6 个分组）。趣味层关闭时，"成长与陪伴"整组不出现。

首页仍然是山门，但主按钮是「开始今日学习」，快捷卡是文献 / 复盘 / 知识库 / 领域，项目退为一行弱化文字链接——**项目在侧栏里有位置，在首页上不抢注意力**。

## 七、升级与兼容

| 项 | 1.0 的处理 |
| --- | --- |
| 数据库结构 | **重建为 v2**（`wendao.db`，`user_version=2`），旧库不兼容、需重新开始 |
| 旧库能否直接用 | 能。启动时执行一次文案归一化，只改仍是出厂默认的标签 |
| 个人化 | 自定义导航名、排序、领域名、阶段自述逐字保留 |
| 趣味层 | 新库默认关闭；已有库保留原值，不擅自改变你的界面 |
| 版本号 | `1.0.0`（`VERSION`、`pyproject.toml`、`version.py` 同步） |

**数据库已重建**：1.0 废弃 3.x 的 `wendao-v3-clean.db`，改用 `wendao.db`（schema v2），并引入 `schema_migrations` 表记录版本。旧库不会被读取，也不会被自动迁移——这是"重新设计建表"的代价，必须在升级时明确告知。

**迁移执行器已补齐**（1.1.0）：版本化步骤 + 迁移前快照 + 失败回滚，见 `core/migrations.py` 与 `tests/test_migrations.py`。从 1.1 起，schema 演进不再需要重建库。

## 八、验收

1.0 的验收不看功能数量，看四件事：

1. 打开首页，**不需要滚动和思考**就能知道今天做什么；
2. 完成一个任务，**必然**留下一份可被追问的证据；
3. 打开任意项目，能看到**六环里哪一环是空的**；
4. 连续两周不打开趣味层，**不影响任何科研动作**。

四条都成立，才算收敛完成；任何一条不成立，说明还有功能没被放对位置。
